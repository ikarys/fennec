      Agent

      fennec reads and runs commands in the folder you pick, git or not, with your home folder hidden (the network stays open to install what is needed). It changes nothing until you allow it. The discussion's cost is on the right.

      Partial guarantees: sensitive zones and tests are enforced, but the guard and the decision registry are not hardened yet.

      How it works
      1. Pick a project: a folder on your disk ("+ project").
      2. Describe your task, as to a colleague, then "Start". If it is vague, fennec discusses it with you.
      3. Once it is clear, fennec answers with "done when": what you will be able to see once it is finished. Validate it or correct it.
      4. fennec works alone, then tries the result and shows you the proof.
      5. You look at the proof and the changes, then choose: commit, or pass (the work is set aside).
      6. Everything stays in the history: click a task to see again what was asked, done and proven.

      The team ("Team") picks the roles that work on the project; "Settings" picks the model.

            "In the folder": you see the work live, on a work branch. "Apart": your folder changes only at commit. The change applies to the next tasks. Each work's isolation: network to install dependencies, offline verification, no access to your home folder, read-only git history, capped memory; a failed try is undone without a trace.

            Settings

                Instructions every agent follows on each task, in all your projects, written in ~/.config/fennec/rules.md. The ones for a single project are on the project's page.

                  Commands and files

                  Checked before each command, read or write of an agent, whatever the model. "Deny" refuses; "Ask" waits for your answer in a discussion, and a task does without; "Allow" lifts an ask, never a deny. Kept in ~/.config/fennec/guard.json, never in a project.

                    fennec starts the Fleet's tasks on its own, in this order, as soon as a slot is free. Each works apart: once ready, it waits for you without holding up the next. When nothing works, fennec prepares the next ones: if it has a question, it comes in "For you". Stopping it does not cut what runs.

                    They apply to all your projects: the team sees the name and goal of each enabled skill, and reads it when the task needs it. They come from ~/.claude/skills and your plugins, from ~/.config/fennec/skills or from a project's .claude/skills folder.

                      A plugin tells you elsewhere (Discord, Telegram, Teams, ntfy…) when a task has a question, is ready or fails. Each is a folder of ~/.config/fennec/plugins with a plugin.json; it runs on your machine with your rights, only once enabled. A plugin that relays (the bundled Telegram bot) also lets you validate, drop or answer from the chat, for the senders in its "allow" list only; each decision is written in the Journal.

                        What fennec left behind when a work was cut short (a restart, a stop at the wrong time): no task uses it anymore. Tick what you want to delete.
